## Формат общения с пользователем (задано 2026-09-13)

1. **Отчёты о выполнении — короткие.** Пользователю достаточно: шаг прошёл нормально / были затруднения. Развёрнутое изложение — только по отдельной просьбе («разверни»).
2. **Вопросы — нумерованные.** Если вопросов много — выносить в отдельный файл, а не в чат.
3. **К каждому вопросу — варианты решения.** Не задавать вопрос без предложенных вариантов.
4. **Порядок ответа:** сначала краткий отчёт, потом вопросы. Вопросы — в конце.

## Соглашения по git

- `.workbuddy-ai/skills/` версионируется вместе с проектом (не в `.gitignore`) — проектные скиллы едут в репозиторий.
- Отправка — через `push.bat` (двойной щелчок или `push -m "..."`). Из bash: `bash push.sh`.
- ⛔ **Не использовать `where bash`** для поиска интерпретатора: `C:\Windows\System32\bash.exe` — это WSL-лаунчер, он даёт код 127. Нужен только `C:\Program Files\Git\bin\bash.exe`.
- При правке `.bat` проверять CRLF: `python -c "d=open('push.bat','rb').read(); print('bare LF:', d.count(b'\n')-d.count(b'\r\n'))"`.
- `git status` с `[gone]` **не означает**, что push не прошёл — сначала сверить `git ls-remote origin refs/heads/master` с `git rev-parse HEAD`. Дефект локального ref-хранилища (следы namespace `refs/cline/`) лечится записью `printf '<sha>\n' > .git/refs/remotes/origin/master`.
- `prompt.txt` в корне — черновик затравки, осознанно **не** в git.
