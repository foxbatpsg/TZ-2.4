# EPIC-07. MCP
Веха: M6. Gate: G-07.
Входной Gate: G-06; компоненты EPIC-03/04/05 доступны.
Общий DoD: DOD-ALL (`TASK EXECUTION CONTRACT v1.0` §22).
Источник контрактов: MCP TOOL CONTRACTS v1.1.

> **Инструкция исполнителю (Context Header).** Карточки этой главы — pre-Context-Header материал. Перед выполнением любой `E07-CYY` собрать полный Context Header по `TASK EXECUTION CONTRACT v1.0` §4, подставив `TASK-ID=E07-CYY`, `ALLOWED_FILES` — по графу модулей `ARCHITECTURE.md` §2, `BASELINE_ID` — текущий baseline, `RELATED_ADR`/`BLOCKED_BY` — `NONE`, если не указано иное в карточке.
Общие условия каждой tool-карточки:
- UUID, типы, обязательность и ownership проверяются до side effects.
- MCP вызывает только Application/Core API.
- operation_id уникален для вызова; бизнес-идемпотентность проверяет Core.
- Нормативные ERRORS/RETRY/SIDE EFFECTS берутся из контракта `MCP TOOL CONTRACTS v1.1` §N — раздел по группе инструмента (§1 Planning, §2 Retrieval, §3 Reading, §4 Documents, §5 Study Management, §6 Working Memory, §7 Cache/Diagnostics, §8 Report, §9 Job Management); в карточке они не дублируются.
- Лимиты проверяются на фактическом сериализованном UTF-8 ответе.
- Любой превышенный output limit возвращает RESPONSE_TOO_LARGE.
- Unit mocks: FakeApplicationAPI, FakeClock, fake serializer.
- Component tests: реальный MCP transport и временная SQLite.
- Budget policy определена в `BUDGET CONTRACT v1.0` (`Q-04` закрыт); переносить её в MCP запрещено.

## E07-C01

**Название задачи:** Реализовать MCP stdio transport и регистрацию tools.

**Контекст и техническая цель:** Корректный протокол без прямого доступа к domain state.

**Входные данные и зависимости:** G-06; A-19/A-20.

**Чёткие технические требования к реализации:** Использовать версионированный SDK;
bootstrap, schemas, registration, Application API proxy,
protocol/domain error mapping. Отдельный transport writer; диагностика в stderr.
Timeout одного вызова не уничтожает сервер.

**[ОБЯЗАТЕЛЬНО] Требования к Unit-тестированию:** Unknown method;
malformed request; duplicate tool name; неверная schema;
domain error mapping; разделение protocol error (JSON-RPC code) и domain error (`A-19`, `05` §16);
debug print; exception traceback.
Моки: Application API и transport stream.

**Критерии приёмки:** Валидный JSON-RPC после каждого сбойного сценария;
нет прямых repository/FSM calls из tool handlers; DOD-ALL.

## E07-C02

**Название задачи:** Реализовать общий lifecycle, timeout и output guard.

**Контекст и техническая цель:** Одинаковые защитные правила всех инструментов.

**Входные данные и зависимости:** E07-C01; E03-C05; Q-04 (закрыт — `BUDGET CONTRACT v1.0`).

**Чёткие технические требования к реализации:** Привязать operation_id,
runtime FSM, дедлайн, bounded retry, serialized-byte limit,
structured errors. Поздний ответ после timeout не меняет completed outcome.
Не выполнять automatic retry для инструмента, которому он запрещён.

**[ОБЯЗАТЕЛЬНО] Требования к Unit-тестированию:** Ответ на deadline;
deadline+ε; UTF-8 bytes больше количества символов;
nested oversized payload; repeated timeout; late completion;
retryable=false.
Моки: FakeClock, serializer, runtime FSM.

**Критерии приёмки:** Transport остаётся отзывчивым;
лимиты не обходятся Unicode или nested arrays; DOD-ALL.
