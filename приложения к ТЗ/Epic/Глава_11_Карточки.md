## E11-C01

**Название задачи:** Собрать portable layout и bootstrap package.

**Контекст и техническая цель:** Запуск приложения из переносимого каталога.

**Входные данные и зависимости:** G-10; environment matrix Q-12 (закрыт — `02` §5.3, TARGET; численные критерии после `S-13`).

**Чёткие технические требования к реализации:** Упаковать runtime/application/config/
dependency manifest; отделить пользовательские data/logs/backups.
Не включать production DB, credentials и приватные fixtures.
Пути разрешать относительно application data policy, не текущего cwd.
Обновление приложения не перезаписывает пользовательские проекты.
Включить словарь лемматизатора morphology (`A-25`) и зафиксировать его версию/хеш в dependency manifest (согласованно с morphology version).

**[ОБЯЗАТЕЛЬНО] Требования к Unit-тестированию:** Layout manifest;
запрещённый secret file; путь с кириллицей/пробелами;
другой cwd; повтор распаковки; существующая пользовательская БД.
Моки: filesystem и package manifest.

**Критерии приёмки:** Пакет не содержит пользовательских данных;
запуск не зависит от IDE и source checkout; DOD-ALL.

## E11-C02

**Название задачи:** Реализовать environment checker и понятную диагностику.

**Контекст и техническая цель:** Объяснять отсутствие зависимостей до запуска Study.

**Входные данные и зависимости:** E11-C01; Q-12 (закрыт — `02` §5.3, TARGET), Q-13 (закрыт — вне MVP, `EPIC SPECIFICATIONS` §12).

**Чёткие технические требования к реализации:** Проверять Python/runtime,
SQLite/FTS5, morphology component, права, свободное место,
config/schema compatibility и локальный backend.
Отдельно проверять: словарь лемматизатора читается и морфология не работает
в degraded fallback (`A-13`/`A-25`); SQLite-FTS5 доступен и поддерживает
`rebuild_all` (`A-24`); локальный backend относится к классу `A-22` (12–14B Q4/Q5).
Отличать отсутствие GPU от ошибки: GPU не обязателен.
Не устанавливать автоматически неизвестные компоненты.
Diagnostic token не реализуется в MVP — Q-13 закрыт решением «не вводится в MVP» (`EPIC SPECIFICATIONS` §12).

**[ОБЯЗАТЕЛЬНО] Требования к Unit-тестированию:** Нет FTS5;
нет morphology; недоступный backend; read-only каталог;
мало диска; новый schema version; отсутствие GPU.
Моки: system probes, filesystem, backend health.

**Критерии приёмки:** Сообщение содержит причину и действие пользователя;
нет скрытого привилегированного доступа; DOD-ALL.

## E11-C03

**Название задачи:** Упаковать backup/recovery flow и инструкции.

**Контекст и техническая цель:** Восстановление без разработчика и без потери исходных данных.

**Входные данные и зависимости:** E11-C01/C02; E02-C08;
закрытые Q-01 (`03` §25.2–25.3)/Q-11 (`06` §13) для расширенных сценариев.

**Чёткие технические требования к реализации:** Пользовательский запуск backup,
manifest/checksum/schema verification и restore в безопасный destination.
Документировать recovery после crash, перенос portable folder,
ограничения версий и действия при повреждённой БД.
Не советовать копировать активный .db без WAL-safe backup.

**[ОБЯЗАТЕЛЬНО] Требования к Unit-тестированию:** Неверный checksum;
несовместимая schema; занятый destination;
нехватка места; частично записанный backup;
повтор восстановления.
Моки: filesystem и backup service.
Component: восстановление копии в чистой Windows-среде.

**Критерии приёмки:** Инструкция воспроизводится по шагам;
исходные данные остаются нетронутыми при ошибке; DOD-ALL.

## E11-C04

**Название задачи:** Провести portable release Gate G-11.

**Контекст и техническая цель:** Подтвердить эксплуатационную готовность поставки.

**Входные данные и зависимости:** E11-C01…C03; Q-12/Q-13 закрыты.

**Чёткие технические требования к реализации:** Clean Windows launch без IDE,
missing-dependency diagnostics, CPU-only execution,
создание Project/Study, закрытие/перезапуск, сохранность данных,
backup/recovery и перенос каталога.
Зафиксировать package checksum, версии runtime и release evidence.

**[ОБЯЗАТЕЛЬНО] Требования к Unit-тестированию:** Release manifest без checksum;
неожиданная GPU dependency; пропущенный обязательный компонент;
stale acceptance bundle; Q-13 закрыт (token вне MVP); missing recovery evidence.
Моки: package/gate manifests.
Acceptance: фактический запуск поставки в целевой Windows-среде.

**Критерии приёмки:** Portable запускается без IDE;
данные переживают перезапуск и перенос по утверждённой policy;
M10 объявляется достигнутой только после G-11 PASS; DOD-ALL.
