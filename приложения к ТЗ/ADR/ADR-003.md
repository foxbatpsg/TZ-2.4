# ADR-003 — Уникальность SourceRelation при claim-связях (N-02)

**Статус:** Accepted — 2026-09-14.
**Закрывает:** `N-02` (P0-блокер); ожидание `S-11` снято.
**Нормативная норма:** «Уникальность SourceRelation (N-02, ADR-003)» — `03_Модель данных и хранение.md` §8a (первичный источник).
**Назначение файла:** адресная карточка решения для исполнителей задач (`RELATED_ADR: ADR-003`). Формулировки ниже перенесены дословно из `REVIEW-REGISTRY.md` §3 (N-02); нормативной правкой файл не является, при расхождении приоритет — у ТЗ.

## Контекст

Двойное противоречие в `03` §8a: (1) `claim_id` присутствует в схеме и признан «связью с конкретным Claim (Q-02)», но составной UNIQUE задан только по `(study_id, source_source_id, target_source_id)` — значит, для одной пары источников нельзя сохранить разные отношения по двум разным Claim; (2) у поля `claim_id` нет явного `FOREIGN KEY`.

ТЗ `03` стр. 239 объявляет `claim_id` необязательным (`NULL, если связь общая`), а стр. 250 добавляет «Обязателен составной уникальный индекс на пару `(study_id, source_source_id, target_source_id)`» — без учёта заполненного `claim_id`. Прямой конфликт с Q-02 (ТЗ `03` стр. 246, `01` стр. 341–345), где независимость оценивается именно на уровне Claim.

## Решение

Принят вариант «два частичных UNIQUE-индекса + FK». Норма внесена в `03` §8a: для claim-specific связей — `UNIQUE (study_id, source_source_id, target_source_id, claim_id) WHERE claim_id IS NOT NULL`; для общих связей — `UNIQUE (study_id, source_source_id, target_source_id) WHERE claim_id IS NULL` (одна четвёрка без условия `WHERE` не годится: в SQLite `NULL ≠ NULL`, и защита общих связей перестала бы работать). `claim_id` объявлен `FOREIGN KEY REFERENCES Claim`. Обязательна проверка принадлежности Claim и обоих Source одной Study; при конфликте claim-specific связь переопределяет общую; миграция проверяет существующие дубликаты **до** применения и не удаляет их молча.
