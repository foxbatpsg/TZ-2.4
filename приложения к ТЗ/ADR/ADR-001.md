# ADR-001 — Профили исполнения и владелец агентного цикла (N-01)

**Статус:** Accepted — 2026-09-14.
**Закрывает:** `N-01` (P0-блокер).
**Нормативная норма:** «Профили исполнения и владелец агентного цикла (N-01, ADR-001)» — `02_Архитектура и системные принципы.md` §3a (первичный источник); уточняющая сноска — `05_Взаимодействие с LLM и протокол MCP.md` §3.
**Назначение файла:** адресная карточка решения для исполнителей задач (`RELATED_ADR: ADR-001`). Формулировки ниже перенесены дословно из `REVIEW-REGISTRY.md` §3 (N-01); нормативной правкой файл не является, при расхождении приоритет — у ТЗ. Полный разбор замечания — в реестре.

## Контекст

Схема «LLM → MCP → Core» пропускает звено host/client. Модель возвращает tool calls по HTTP, но сама не является stdio-клиентом. Для автономного GUI-приложения владелец агентного цикла не назначен.

ARCHITECTURE §1.4 п.1 требует «единый процесс, один активный MCP stdio-сервер на процесс», а §4.1 объявляет MCP **единственным** каналом LLM→Core. Одновременно §1.2 указывает для LLM «OpenAI-compatible HTTP API». Эти два положения не сведены в единую процессную схему.

Риск: агент-исполнитель самостоятельно изобретёт схему запуска → расхождение реализаций у разных исполнителей; риск одновременного владения одной Project DB двумя Core.

## Решение

Принят вариант 3 (`OPEN-QUESTIONS-for-Architector.md`, вопрос 1) — два профиля исполнения. Норма «Профили исполнения и владелец агентного цикла (N-01, ADR-001)» внесена в `02` §3a: **desktop orchestration** (по умолчанию: Orchestrator в процессе приложения, обращение к LLM по HTTP, вызовы инструментов через единый ToolDispatcher) и **headless `--mcp-stdio`** (агентный цикл ведёт внешний MCP-клиент, stdio-адаптер транслирует вызовы в тот же ToolDispatcher, набор — те же 23 инструмента). Явно зафиксировано: MCP — протокол **вызова инструментов**, а не протокол инференса; обращение к LLM идёт отдельным каналом (`05` §1–2). Один процесс ядра на файл Project DB, второй запуск → `PROJECT_LOCKED`; ядро не запускает LLM как дочерний процесс. Уточняющая сноска внесена в `05` §3.
